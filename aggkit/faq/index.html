    Frequently Asked Questions (FAQ)¶

    General Questions¶

    What is AggKit?¶

    AggKit is a modular framework that enables blockchain networks to connect to the AggLayer. It provides the necessary components for cross-chain bridging, certificate generation, and state synchronization between L1 and L2 networks.

    How does AggKit differ from other bridging solutions?¶

    AggKit is specifically designed for AggLayer integration and offers:

    • Modular architecture - Use only the components you need
    • Zero-knowledge proofs - Cryptographic security guarantees
    • Production-ready - Battle-tested with comprehensive testing
    • Multi-network support - Works with various EVM-compatible chains

    Which blockchain networks are supported?¶

    AggKit supports:

    • Polygon PoS - Polygon Proof-of-Stake mainnet
    • Polygon zkEVM - Zero-knowledge rollups
    • Optimism - Optimistic rollups
    • Custom Networks - Any EVM-compatible blockchain

    Technical Questions¶

    What is a Certificate in AggKit?¶

    A certificate is a cryptographic proof that contains bridge state information. It includes:

    • Bridge state proofs (Merkle proofs)
    • Transaction data for bridge operations
    • Metadata for verification
    • Signatures from authorized parties

    Certificates are submitted to the AggLayer for aggregation and final settlement.

    How does the Global Exit Root (GER) work?¶

    The Global Exit Root is calculated as: 

    GER = hash(Mainnet Exit Root, Rollup Exit Root)

    It enables cross-chain bridging by providing a unified root that encompasses all network states. The AggOracle component propagates GER updates from L1 to L2 networks.

    What database does AggKit use?¶

    AggKit uses SQLite as the default database with automatic migrations. SQLite provides:

    • Zero-configuration setup
    • ACID compliance
    • Cross-platform compatibility
    • Sufficient performance for most use cases

    For high-scale deployments, the database layer can be extended to support PostgreSQL or other databases.

    How are blockchain reorganizations handled?¶

    AggKit includes a reorg detector that:

    • Monitors for chain reorganizations
    • Reverts affected state changes
    • Re-processes blocks after the reorganization
    • Ensures data consistency across components

    Configuration Questions¶

    How do I configure AggKit for my network?¶

    1. Create a TOML configuration file based on the templates in test/config/
    2. Set network-specific values like RPC URLs and contract addresses
    3. Enable required components using the --components flag
    4. Override with environment variables if needed

    Example: 

    ./aggkit run --cfg mynetwork.toml --components aggsender,bridge_service

    Can I run only specific components?¶

    Yes! AggKit’s modular architecture allows you to run only the components you need:

    # Only certificate generation
./aggkit run --cfg config.toml --components aggsender

# Only API service
./aggkit run --cfg config.toml --components bridge_service

# Multiple components
./aggkit run --cfg config.toml --components aggsender,aggoracle,bridge_service

    How do I configure environment variables?¶

    Environment variables follow the pattern AGGKIT_<SECTION>_<KEY>:

    # Override log level
export AGGKIT_LOG_LEVEL=debug

# Override database name
export AGGKIT_DATABASE_NAME=prod_aggkit.db

# Override bridge service port
export AGGKIT_BRIDGE_SERVICE_PORT=9090

    Deployment Questions¶

    Can AggKit run in production?¶

    Yes! AggKit is production-ready and includes:

    • Comprehensive test coverage with unit and integration tests
    • Error handling and recovery mechanisms
    • Monitoring and observability features
    • Security best practices implementation

    How do I scale AggKit?¶

    AggKit supports several scaling approaches:

    1. Horizontal scaling - Run components on separate machines
    2. Database sharding - Split data across multiple databases
    3. Load balancing - Distribute API requests
    4. Component specialization - Dedicated instances for specific components

    What are the hardware requirements?¶

    Minimum requirements: - CPU: 2+ cores - RAM: 4GB+ - Storage: 20GB+ SSD - Network: Stable internet connection

    Production requirements vary based on: - Number of transactions processed - Number of networks connected - API request volume - Data retention requirements

    Development Questions¶

    How do I contribute to AggKit?¶

    1. Fork the repository on GitHub
    2. Create a feature branch for your changes
    3. Write tests for new functionality
    4. Run the test suite to ensure everything works
    5. Submit a pull request with a clear description

    See the repository’s contributing guidelines for detailed instructions.

    How do I run tests locally?¶

    # Unit tests with coverage
make test-unit

# Linting
make lint

# Vulnerability scanning
make vulncheck

# E2E tests (requires Kurtosis CDK)
cd test/ && make test-e2e

    How do I debug issues?¶

    1. Enable debug logging: 

      export AGGKIT_LOG_LEVEL=debug

    2. Check component status: 

      curl http://localhost:8080/health

    3. Monitor database state: 

      sqlite3 aggkit.db ".tables"
sqlite3 aggkit.db "SELECT * FROM certificates LIMIT 10;"

    4. Check blockchain connectivity: 

      curl -X POST -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
  http://localhost:8545

    Security Questions¶

    How secure is AggKit?¶

    AggKit implements several security measures:

    • Zero-knowledge proofs for cryptographic security
    • TLS encryption for all external communication
    • Input validation for all external data
    • Rate limiting to prevent abuse
    • Secure key management with HSM support
    • Audit logging for all operations

    How are private keys managed?¶

    AggKit supports multiple key management approaches:

    • File-based keystores with password protection
    • Hardware Security Modules (HSM) for production
    • Environment variables for development
    • Key derivation from secure seeds

    Never commit private keys to version control or logs.

    How do I report security issues?¶

    For security vulnerabilities:

    1. Do NOT create public issues
    2. Email security concerns to the maintainers
    3. Provide detailed information about the vulnerability
    4. Allow time for patch development before disclosure

    Troubleshooting¶

    AggKit won’t start - what should I check?¶

    1. Configuration file - Ensure it’s valid TOML format
    2. Network connectivity - Test RPC endpoints
    3. Database permissions - Ensure write access to database location
    4. Port availability - Check if configured ports are free
    5. Dependencies - Verify Go version and build success

    Bridge transactions are not being processed¶

    Check:

    1. Component status - Ensure BridgeSync is running
    2. RPC connectivity - Verify both L1 and L2 connections
    3. Event filtering - Check if events are being detected
    4. Database state - Look for errors in bridge_events table
    5. Block synchronization - Ensure components are synced

    Certificates are not being submitted¶

    Verify:

    1. AggSender configuration - Check RPC URL and credentials
    2. Certificate generation - Look for errors in logs
    3. Network connectivity - Test connection to AggLayer
    4. Proof generation - Ensure proof service is accessible
    5. Database state - Check certificate status

    API responses are slow¶

    Optimize by:

    1. Database indexing - Ensure proper indexes exist
    2. Connection pooling - Configure appropriate pool sizes
    3. Caching - Enable caching for frequently accessed data
    4. Rate limiting - Implement appropriate limits
    5. Hardware scaling - Increase resources if needed

    Performance Questions¶

    What throughput can AggKit handle?¶

    Performance depends on several factors:

    • Network latency to L1/L2 RPCs
    • Database performance (SQLite vs PostgreSQL)
    • Hardware specifications
    • Component configuration
    • Transaction complexity

    Typical ranges: - Certificate generation: 10-100 certificates/minute - Bridge events: 1000+ events/minute - API requests: 100+ requests/second

    How do I optimize performance?¶

    1. Use SSD storage for database
    2. Increase connection pools for RPC clients
    3. Enable database indexes for frequent queries
    4. Configure appropriate batch sizes
    5. Monitor and profile bottlenecks
    6. Scale horizontally when needed

    Can I use PostgreSQL instead of SQLite?¶

    Currently, AggKit uses SQLite by default. PostgreSQL support can be added by:

    1. Implementing database driver interface
    2. Updating migration system for PostgreSQL
    3. Testing thoroughly with the new backend
    4. Contributing back to the project

    This is a potential area for community contribution.
