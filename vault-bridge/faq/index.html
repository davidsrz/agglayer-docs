    Vault Bridge FAQ¶

    This FAQ addresses common questions about Vault Bridge, covering technical implementation, integration considerations, and operational aspects.

    General Questions¶

    What is Vault Bridge?¶

    Vault Bridge is a protocol that enables chains and applications to generate native yield on Total Value Locked (TVL) by putting bridged assets to work. It transforms idle bridged assets into productive capital, generating sustainable revenue for Layer 2 networks without requiring new infrastructure or changes to existing canonical bridges.

    How does Vault Bridge differ from other yield protocols?¶

    Vault Bridge is unique in several ways:

    • Cross-chain native: Designed specifically for multi-chain environments
    • Bridge-integrated: Works seamlessly with existing bridge infrastructure
    • Revenue sharing: Provides direct revenue streams to participating chains
    • No infrastructure changes: Requires no modifications to existing bridges
    • ERC-4626 compatible: Uses standard vault interfaces for easy integration

    Which chains support Vault Bridge?¶

    Agglayer-connected chains receive full support with no fees: - All CDK chains connected to Agglayer - Full Native Converter functionality - 100% revenue sharing

    Non-Agglayer chains have limited support: - Third-party bridge integration required - Revenue sharing fees apply - Limited Native Converter functionality - Contact team for full support roadmap

    What assets are supported?¶

    Currently supported assets include: - WETH: Wrapped Ethereum - USDC: USD Coin - WBTC: Wrapped Bitcoin

    Additional assets are being evaluated based on: - Market demand - Available yield strategies - Liquidity requirements - Risk assessment

    Technical Questions¶

    How are vbTokens different from regular tokens?¶

    vbTokens (Vault Bridge Tokens) are:

    • 1:1 backed: Always redeemable for underlying assets
    • Yield-generating: Underlying assets generate yield for the protocol
    • Cross-chain compatible: Can be bridged and used across multiple chains
    • ERC-4626 compliant: Follow standard vault token interfaces
    • Non-appreciating for users: Users don’t directly receive yield - it goes to chains/apps

    How does the Migration Manager work?¶

    The Migration Manager coordinates asset movement from Layer 2 to Layer 1:

    1. Accumulation: Native Converters accumulate backing assets on Layer 2
    2. Threshold trigger: Migration triggers when threshold is reached
    3. Cross-chain message: Migration request sent via Agglayer bridge
    4. Validation: Migration Manager validates the request and proofs
    5. Execution: Assets are deposited into Vault Bridge Token on Layer 1
    6. Yield deployment: Assets are placed into yield-generating vaults

    What are the security considerations?¶

    Smart contract risks: - Standard DeFi protocol risks apply - Contracts audited by reputable firms - Built on proven infrastructure (Morpho, ERC-4626)

    Cross-chain risks: - Secured by Agglayer’s ZK proof system - Pessimistic proofs as backup security - Fraud proof mechanisms available

    Yield strategy risks: - Risk managed by Gauntlet and Steakhouse Financial - Diversified across multiple yield sources - Emergency exit mechanisms implemented

    How is yield calculated and distributed?¶

    Yield generation: - Assets deposited into ERC-4626 compatible external vaults - Multiple yield strategies managed by expert curators - Continuous compounding of generated returns

    Distribution: - 100% to Agglayer-connected chains - Subject to fees for non-Agglayer chains - Configurable distribution within chain ecosystems - Real-time streaming via smart contracts

    Integration Questions¶

    How do I integrate Vault Bridge into my DeFi protocol?¶

    Basic integration steps:

    1. Install dependencies: Add Vault Bridge contracts to your project
    2. Implement interfaces: Use standard ERC-4626 interfaces
    3. Handle vbTokens: Treat vbTokens as interest-bearing assets
    4. Add bridge support: Integrate cross-chain functionality if needed
    5. Test thoroughly: Use comprehensive test suites

    See our Integration Guide for detailed instructions.

    Can I use Vault Bridge with existing bridges?¶

    Agglayer bridges: Full compatibility with no modifications needed

    Third-party bridges: - Supported through bridge adapters - May require custom integration work - Limited functionality compared to native integration - Contact team for specific bridge support

    What are the gas costs for Vault Bridge operations?¶

    Layer 1 operations (Ethereum): - Deposit: ~150,000 gas - Withdraw: ~120,000 gas - Cross-chain bridge: ~200,000 gas

    Layer 2 operations: - Native conversion: ~80,000 gas - Deconversion: ~90,000 gas - Bridge operations: ~140,000 gas

    Gas costs vary based on network congestion and specific operations.

    How do I handle slippage and MEV protection?¶

    Built-in protections: - Maximum 1% slippage tolerance - Price impact thresholds - Rate limiting mechanisms - Emergency circuit breakers

    Additional recommendations: - Use preview functions to estimate outputs - Implement deadline parameters - Consider flashloan MEV protection - Monitor for unusual activity

    Troubleshooting¶

    Common Integration Issues¶

    Issue: “Insufficient allowance” error Solution: Ensure proper token approvals before calling deposit functions

    Issue: Cross-chain transactions not completing Solution: Check bridge status and wait for finality confirmations

    Issue: Yield not appearing Solution: Yield goes to chains/protocols, not individual users

    Issue: Migration not triggering Solution: Check if migration threshold has been reached

    Performance Optimization¶

    Gas optimization: - Batch operations when possible - Use efficient data structures - Minimize external calls - Implement proper caching

    User experience: - Provide clear transaction feedback - Implement proper loading states - Handle edge cases gracefully - Offer transaction status updates

    Debugging Tips¶

    Cross-chain debugging: - Verify transaction completion on source chain - Check bridge status APIs - Confirm destination chain state - Validate proof submission
