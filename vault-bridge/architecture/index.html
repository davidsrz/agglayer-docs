    Vault Bridge Architecture¶

    This document provides a comprehensive technical overview of the Vault Bridge protocol architecture, including its core components, interaction patterns, and integration points with the Agglayer ecosystem.

    High-Level Architecture¶

    Vault Bridge operates across two chain types: - Layer X (Primary Chain): Where assets are deposited and yield is generated - Layer Y (Secondary Chain): Where vbTokens are used and DeFi interactions occur

    graph TB
    subgraph "Layer X (Primary Chain)"
        VBT[Vault Bridge Token Contract]
        YV[Yield Vault ERC-4626]
        MM[Migration Manager]
        VBT --> YV
        MM --> VBT
    end

    subgraph "Layer Y (Secondary Chain)"
        NC[Native Converter]
        CT[Custom Token]
        DEFI[DeFi Protocols]
        NC --> DEFI
        CT --> DEFI
    end

    subgraph "Agglayer Bridge"
        UB[Unified Bridge]
        VBT <--> UB
        NC <--> UB
    end

    subgraph "External Systems"
        MORPHO[Morpho Vaults]
        GAUNTLET[Gauntlet Risk Management]
        STEAKHOUSE[Steakhouse Financial]
        YV --> MORPHO
        GAUNTLET --> YV
        STEAKHOUSE --> YV
    end

    Core Components¶

    1. Vault Bridge Token Contract¶

    The Vault Bridge Token is the core component that implements multiple interfaces:

    Interfaces¶

    • ERC-20: Standard token functionality for vbTokens
    • ERC-4626: Vault standard for deposit/withdraw operations
    • Unified Bridge Extension: Integration with Agglayer’s bridge system

    Key Functions¶

    // Core ERC-4626 functions
function deposit(uint256 assets, address receiver) external returns (uint256 shares);
function withdraw(uint256 assets, address receiver, address owner) external returns (uint256 shares);

// Bridge integration functions  
function depositAndBridge(uint256 assets, address receiver, uint32 destinationNetwork) external;
function claimAndRedeem(uint256 shares, address receiver, address owner) external;

    Responsibilities¶

    • Asset Management: Handles deposits and withdrawals of underlying assets
    • vbToken Minting: Mints and burns vbTokens in 1:1 ratio with underlying assets
    • Yield Integration: Deposits assets into external yield-generating vaults
    • Bridge Operations: Facilitates cross-chain vbToken transfers
    • Migration Support: Accepts migrated assets from Layer Y via Migration Manager

    2. Migration Manager¶

    The Migration Manager coordinates the movement of backing assets from Layer Y to Layer X.

    Architecture Pattern¶

    graph LR
    NC[Native Converter L2] --> MM[Migration Manager L1]
    MM --> VBT[Vault Bridge Token L1]
    VBT --> YV[Yield Vault]

    Key Responsibilities¶

    • Migration Coordination: Manages asset transfers from Native Converters to Vault Bridge Tokens
    • Cross-Chain Synchronization: Ensures proper accounting across chains
    • Security Validation: Verifies migration authenticity and prevents double-spending
    • Batch Processing: Optimizes gas costs through batched migration operations

    Implementation Details¶

    • Shared across all vbTokens (single Migration Manager per deployment)
    • Integrates with Agglayer’s cross-chain messaging system
    • Implements rate limiting and validation mechanisms
    • Maintains migration audit trail for transparency

    3. Native Converter¶

    The Native Converter enables direct vbToken creation on Layer Y without bridging from Layer X.

    Operational Model¶

    graph TD
    UA[User Assets] --> NC[Native Converter]
    NC --> VBT_L2[vbToken on L2]
    NC --> MM[Migration to L1]
    MM --> VBT_L1[Vault Bridge Token L1]
    VBT_L1 --> YV[Yield Generation]

    Key Features¶

    • Direct Conversion: Convert bridged underlying assets to vbTokens 1:1 on Layer Y
    • Liquidity Management: Maintains liquidity reserves for deconversion operations
    • Migration Support: Batches backing assets for migration to Layer X
    • Bridge Integration: Functions as Unified Bridge extension

    Liquidity Guarantees¶

    • Guaranteed Liquidity: Deconversion guaranteed up to specific percentage of deposits
    • Migration Triggers: Automated migration when liquidity thresholds are reached
    • Reserve Management: Dynamic liquidity management based on usage patterns

    4. Custom Token¶

    Custom Tokens provide enhanced functionality for vbTokens on Layer Y.

    Use Cases¶

    • Enhanced Interfaces: Add specialized interfaces (e.g., WETH9 compatibility for vbETH)
    • Custom Logic: Implement chain-specific behaviors and optimizations
    • Protocol Integration: Seamless integration with existing Layer Y protocols
    • Upgrade Mechanism: Provide migration path from basic vbTokens to enhanced versions

    Implementation Pattern¶

    contract CustomVBETH is ERC20, IWETH9 {
    IERC20 public immutable vbETH;

    function deposit() external payable {
        // Convert ETH to vbETH via Native Converter
        // Issue Custom Token 1:1
    }

    function withdraw(uint256 amount) external {
        // Burn Custom Token
        // Convert vbETH back to ETH
    }
}

    Integration Patterns¶

    Standard ERC-4626 Integration¶

    For applications already supporting ERC-4626 vaults:

    // Simple integration example
IERC4626 vaultBridgeToken = IERC4626(vbTokenAddress);

// Deposit assets and receive vbTokens
uint256 shares = vaultBridgeToken.deposit(assets, receiver);

// Later: withdraw assets by burning vbTokens  
uint256 assets = vaultBridgeToken.redeem(shares, receiver, owner);

    Bridge-Integrated Operations¶

    For cross-chain operations using Vault Bridge’s bridge extensions:

    // Deposit and bridge in single transaction
IVaultBridgeToken(vbTokenAddress).depositAndBridge(
    assets,
    receiver, 
    destinationNetwork
);

// Claim on destination chain and redeem assets
IVaultBridgeToken(vbTokenAddress).claimAndRedeem(
    shares,
    receiver,
    owner
);

    Native Converter Integration¶

    For applications on Layer Y wanting to work with vbTokens:

    // Convert bridged assets to vbTokens on Layer Y
INativeConverter(nativeConverterAddress).convert(
    underlyingAssets,
    receiver
);

// Deconvert back to underlying assets
INativeConverter(nativeConverterAddress).deconvert(
    vbTokenAmount,
    receiver
);

    Yield Generation System¶

    External Vault Integration¶

    Vault Bridge integrates with external ERC-4626 compatible vaults for yield generation:

    graph TB
    VBT[Vault Bridge Token] --> MORPHO[Morpho Vault]
    MORPHO --> LENDING[Lending Markets]
    MORPHO --> STAKING[Staking Protocols]
    MORPHO --> YIELD[Other Yield Sources]

    GAUNTLET[Gauntlet] --> RISK[Risk Assessment]
    STEAKHOUSE[Steakhouse] --> STRATEGY[Strategy Selection]
    RISK --> VBT
    STRATEGY --> VBT

    Risk Management¶

    Strategy Curation¶

    • Gauntlet: Provides quantitative risk analysis and parameter recommendations
    • Steakhouse Financial: Offers institutional-grade risk management and strategy curation
    • Dynamic Weighting: Strategy allocations based on chain-specific risk profiles

    Risk Mitigation¶

    • Diversification: Spread assets across multiple yield strategies
    • Monitoring: Continuous monitoring of vault performance and security
    • Emergency Procedures: Circuit breakers and emergency withdrawal mechanisms
    • Insurance Integration: Optional integration with DeFi insurance protocols

    Cross-Chain Communication¶

    Agglayer Integration¶

    Vault Bridge leverages Agglayer’s Unified Bridge for secure cross-chain operations:

    Message Types¶

    • Asset Bridging: Standard token transfers with vbToken minting/burning
    • Migration Messages: Backing asset movement from Layer Y to Layer X
    • Yield Distribution: Revenue sharing information and payments
    • Configuration Updates: Cross-chain parameter synchronization

    Security Model¶

    • ZK Proofs: Agglayer’s zero-knowledge proof system validates all cross-chain operations
    • Pessimistic Proofs: Backup security mechanism for additional validation
    • Fraud Proofs: Challenge mechanism for disputed operations
    • Finality Guarantees: Cross-chain operation finality aligned with L1 finality

    Non-Agglayer Chains¶

    For chains not connected to Agglayer:

    Integration Requirements¶

    • Third-Party Bridges: Integration with external bridge providers
    • Limited Functionality: Reduced Native Converter support
    • Revenue Fees: Protocol fees apply for revenue sharing
    • Manual Coordination: Some operations may require manual intervention

    Planned Enhancements¶

    • Universal Adapters: Generic adapters for popular bridge protocols
    • Automated Migration: Improved automation for non-Agglayer chains
    • Enhanced Security: Additional validation for external bridge operations

    Contract Relationships¶

    Inheritance Hierarchy¶

    • VaultBridgeToken: Inherits from ERC20, ERC4626, UnifiedBridgeExtension
    • NativeConverter: Inherits from ERC20, UnifiedBridgeExtension
    • CustomToken: Inherits from ERC20, often implements additional interfaces
    • MigrationManager: Standalone contract with VaultBridgeToken integration

    Dependency Management¶

    • Upgradeable Contracts: Use proxy patterns for upgradeability where needed
    • Immutable Core: Critical logic in immutable contracts for security
    • Modular Design: Components can be independently upgraded or replaced
    • Interface Stability: Stable interfaces to support ecosystem integration

    Performance and Scalability¶

    Gas Optimization¶

    Batch Operations¶

    • Migration Batching: Multiple migrations processed in single transaction
    • Yield Distribution: Bulk distribution to reduce per-chain costs
    • State Updates: Optimized storage patterns to minimize gas costs

    Layer 2 Benefits¶

    • Lower Costs: Reduced transaction costs on Layer Y operations
    • Higher Throughput: More transactions per second for user operations
    • Better UX: Faster confirmation times for interactive operations

    Scalability Considerations¶

    Multi-Asset Support¶

    • Template Contracts: Reusable contract templates for new assets
    • Shared Infrastructure: Common components across all vbTokens
    • Automated Deployment: Streamlined process for adding new assets

    Network Effects¶

    • Liquidity Aggregation: Combined liquidity across all participating chains
    • Yield Optimization: Better rates through larger asset pools
    • Cross-Chain Arbitrage: Opportunities for yield optimization across chains
